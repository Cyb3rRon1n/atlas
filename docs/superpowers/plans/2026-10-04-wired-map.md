# Wired Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The /map becomes a vendor-neutral wired topology: Internet → router (the LAN's default gateway) → network gear → wired endpoints. Wireless devices are hidden by default.

**Architecture:** Two new operator-editable device fields: `connection` (wired / wireless / unknown) and `uplink_id` (the device it plugs into). A pure guess marks devices wireless when the operator hasn't said: a randomized (locally administered) MAC, or kind `phone`. The LAN scan flags the sighting whose IP is the default gateway. `build_graph` draws the tree from these fields. No vendor APIs, nothing new to configure.

**Tech Stack:** Python 3.12, SQLAlchemy 2 (SQLite), stdlib http.server, vendored Cytoscape.js 3.34.3 (no new JS libs), pytest.

**Spec:** `docs/superpowers/specs/2026-09-29-network-inventory-design.md`. This plan adds the "Wired map" section to it (Task 4). The user approved this design in chat on 2026-10-04: vendor-neutral, works on any LAN, UniFi/SNMP auto-fill deferred.

## Global Constraints

- Match the repo's style: heavy vertical spacing, docstrings that explain *why*, no formatter. Read neighbouring code first.
- No new dependencies (Python or JS). Cytoscape stays the vendored, hash-pinned file. No dagre.
- Never put data into `innerHTML`. Build DOM nodes or use `textContent`, as the existing map and device pages do.
- Operator-set fields win over automation. `connection` and `uplink_id` join `EDITABLE` and are locked when set, like the other fields.
- `connection` values are exactly `wired`, `wireless`, `unknown`; the default is `unknown`.
- Existing databases must keep working: new columns are added at startup with `ALTER TABLE ... ADD COLUMN`, idempotently.
- Tests: `python -m pytest tests/` must stay green (run from the repo root, using `.venv`).
- Commits: no Co-Authored-By or other AI-attribution trailers.

**Interfaces produced:**
- `DeviceRecord.connection: str` (default `"unknown"`), `DeviceRecord.uplink_id: int | None` (`ForeignKey("devices.id")`, default None).
- `atlas.devices.store.CONNECTIONS = ("unknown", "wired", "wireless")`.
- `atlas.devices.wiring.effective_connection(device: dict) -> tuple[str, bool]`: returns `(connection, guessed)`. `device` is one `InventoryStore.devices()` entry.
  - If `device["connection"] != "unknown"`, return `(device["connection"], False)`.
  - Else, if any sighting has a MAC whose first octet has the locally-administered bit set (`int(mac[:2], 16) & 0x02`), or `device["kind"] == "phone"`, return `("wireless", True)`.
  - Otherwise `("unknown", False)`.
  - Malformed or missing MACs are skipped, never raised on.
- `atlas.devices.lan.default_gateway(route_text) -> str | None`: the dotted IPv4 gateway of the default route (row destination `00000000`; gateway is `row[2]`, little-endian hex, decode with the existing `_hex_ip`). Returns None if there's no default route.
- `lan.scan` sets `detail={"gateway": True}` on the ARP sighting whose IP equals `default_gateway(route)`.
- Each `InventoryStore.devices()` entry gains `"connection"`, `"uplink_id"`, and `"connection_guessed": bool` (computed with `effective_connection`). The `"connection"` key holds the **effective** value, and the stored value is still recoverable as `"unknown"` when `connection_guessed` is true. `InventoryStore.device(id)` returns the same shape (it already delegates to `devices()`; check this).

### Task 2: Graph: wired tree

**Files:**
- Modify: `atlas/web/graph.py` (`build_graph`)
- Modify: `atlas/web/api.py` (`/api/graph` passes `include_wireless` from `?wireless=1`; same query parsing as `ignored=1`)
- Test: `tests/test_web_graph.py`, `tests/test_web_api.py::test_graph_route`

**Interfaces:**
- Consumes: the device keys from Task 1 (`connection`, `connection_guessed`, `uplink_id`, sightings' `detail.gateway`).
- Produces: `build_graph(devices, topology, include_ignored=False, include_wireless=False) -> {"nodes": [...], "edges": [...], "hidden_wireless": int}`.

Rules:
- **Router:** the shown device with a `lan` sighting where `detail.gateway` is true. If there is one, the root edge is `internet → router` and there is **no** `lan` node. If there isn't one (older data, or a scan without a gateway), keep today's `internet → lan` hub, with `lan` playing the router's role below.
- **Wireless:** a device whose effective `connection` is `wireless` is left out (node and edges) unless `include_wireless`. Exceptions, always shown: the router, any device that is some shown device's `uplink_id`, and any device that is a Proxmox/atlas host with children. Count the left-out devices in `hidden_wireless`. Ignored devices that are also wireless count only when `include_ignored` would have shown them.
- **Edges:** a top-level device (no `parent`) with an `uplink_id` that points at a shown, top-level device other than itself gets `uplink → device`. Otherwise `router (or lan) → device`. Nested guests never get uplink edges. Edge ids stay unique (`e:<source>-<target>`).
- **Node classes** (added to the existing ones): `router` on the router; `infra` on devices of kind `network`; `conn-unknown` on devices whose effective connection is `unknown`; `conn-wireless` on wireless devices shown via `include_wireless`. The node data gains `connection` and `uplink_id`.
- Docker network nodes and Proxmox nesting stay as they are.
- Update the module docstring.

  - A wireless phone (randomized MAC) is hidden and `hidden_wireless == 1`; with `include_wireless` it's shown with `conn-wireless`.
  - An operator-set `wired` phone is shown.
  - An uplink edge replaces the router edge.
  - An uplink to a hidden/ignored/nested device falls back to the router edge.
  - A wireless AP that is someone's uplink stays shown.
  - The existing tests are still valid (adjust the `device()` helper to default `connection="unknown"`, `connection_guessed=False`, `uplink_id=None`).
  - API: `/api/graph?wireless=1` passes through.

- **arrange(cy):** replace the grid with a layered tree.

  - Each node is placed under its parent. A parent's children that have no children of their own (leaves) wrap in a grid of at most 4 columns directly below it. Children with their own subtrees are laid side by side, left to right, each taking its subtree's width.

  - Must not loop on cycles (keep a visited set). Nodes unreachable from `#internet` go in a final grid row.
